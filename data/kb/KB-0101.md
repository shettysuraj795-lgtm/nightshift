# Posting job blocked by lock on accounting document

## Symptoms

The nightly posting job stops part-way through with a lock error on an accounting document. Some invoices in the run are posted and the rest are not.

## Log signatures

- `Object .* is locked by user BATCH_FI`
- `ENQUEUE conflict on table BKPF`

## Background

Financial posting jobs lock each accounting document while they write it. When two posting jobs run in overlapping windows, for example the nightly run and a late intraday run, the second job cannot obtain the lock and cancels. Because the job has already posted part of its selection, a rerun while the lock holder is still active can post the same invoices twice.

## Resolution

1. Confirm the lock holder job has completed
2. Rerun the blocked posting job
3. Raise a change request to separate the schedules

## Risk and approval

- Risk: high
- Approval required before a rerun: yes
- Escalate to: L1
- Never do: `delete_lock_entry`

## Notes

Never remove the lock entry by hand: the holding job may still be writing, and removing the lock can produce duplicate or incomplete postings. The older procedure in KB-0091 that suggested this is superseded by this article.

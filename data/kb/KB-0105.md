# MRP run exceeded its time window

## Symptoms

The nightly MRP run for a plant is cancelled by the scheduler because it is still running at the end of its batch window.

## Log signatures

- `MRP run exceeded its time window`
- `Job cancelled by scheduler: maximum runtime`

## Background

MRP must finish before the morning shift so that planners and the shop floor work from current requirements. Growth in planning volume, a large master data change or a competing job can push the runtime past the window, and the scheduler then cancels the run. Planning results may be only partly updated.

## Resolution

1. Check how far the MRP run progressed before it was cancelled
2. Agree a recovery slot with production planning before the morning shift
3. Rerun MRP for the affected plant in the agreed slot
4. Raise a change request to review the batch window or planning scope

## Risk and approval

- Risk: high
- Approval required before a rerun: yes
- Escalate to: L2
- Never do: `rerun_during_shift_start`

## Notes

Do not restart MRP at shift start without agreement from production planning: a run that overlaps the morning shift changes requirements while planners are already working with them.
